# 《寻迹王国》（开发代号）开发方案

> 项目名称、Logo 与署名尚未确定。“寻迹王国”只作为开发期代号，不会作为最终发行名称。

## 1. 项目目标

- 使用 Cocos Creator 3.8.8 制作竖屏找茬游戏。
- 首发平台：微信小游戏、抖音小游戏；同时保留 Web Mobile/H5 运行能力。
- 第一版包含 5 个完整关卡，每关上下两张对比图、8 个差异点。
- UI 采用原创“轻奇幻皇家竞技场”风格：蓝色菱格、金属包边、金色按钮、盾牌与旗帜元素、厚涂 3D 卡通质感。
- 只借鉴参考图的色彩氛围、层次感和操作反馈，不复制《皇室战争》的角色、Logo、图标、版式或其他受保护资产。
- 接入激励视频、分享、排行榜，并为 AppID、广告位、CDN、后端接口和分享落地参数保留配置入口。

## 2. 第一版范围

### 2.1 游戏流程

1. 启动与资源检查。
2. 首页：开始游戏、关卡入口、排行榜、设置。
3. 关卡选择：显示星级、最佳用时与锁定状态。
4. 对局：倒计时、生命、进度、提示、暂停、加时。
5. 点击差异：上下图同步标记，播放粒子、音效和轻震动。
6. 点击错误：扣除生命并显示短暂错误反馈。
7. 生命耗尽或时间结束：弹出失败面板，可看广告复活。
8. 找齐差异：结算星级、最佳成绩、下一关和分享入口。

### 2.2 五个关卡

| 关卡 | 原创场景主题 | 建议时限 | 差异数 | 难度重点 |
| --- | --- | ---: | ---: | --- |
| 1 | 皇家城堡庭院 | 120 秒 | 8 | 大物件、颜色变化，教学关 |
| 2 | 王室宴会厨房 | 110 秒 | 8 | 食物、餐具、人物配饰 |
| 3 | 炼金术士实验室 | 100 秒 | 8 | 瓶罐、符号、液体颜色 |
| 4 | 骑士团武器库 | 90 秒 | 8 | 武器朝向、盾徽、盔甲部件 |
| 5 | 巨龙宝库 | 80 秒 | 8 | 小型宝物、光影与遮挡变化 |

最终数值全部放在配置文件中，不写死在脚本里，可随测试调整。

## 3. 视觉与 UI 方案

### 3.1 视觉关键词

- 原创轻奇幻、皇家竞技场、卡通厚涂、玩具般体积感。
- 主色：皇家蓝、深海军蓝、暖金、象牙白。
- 状态色：成功绿、警告橙、失败红；保证文字对比度。
- 背景采用低对比蓝色菱格纹，主体面板使用石材/金属包边与柔和投影。

### 3.2 页面布局

- 设计分辨率：750 × 1334，竖屏，按宽度适配并兼顾安全区。
- 顶部：返回、关卡标题、生命、倒计时、设置。
- 中部：上下两张等比例场景图；不拉伸原图，按可用区域等比缩放。
- 两图之间：差异进度与轻量分隔装饰。
- 底部：提示、加时、排行榜/分享入口；关键按钮保持拇指可达。
- 刘海、圆角和平台胶囊按钮区域通过 SafeAreaService 动态避让。

### 3.3 AI 素材生成原则

- 使用内置图像生成能力产出原创素材，不需要额外 API Key。
- 五个关卡先生成“无文字、无 Logo、无水印”的基础场景，再基于基础图制作可控差异版本。
- UI 背板、按钮、徽章和图标使用透明 PNG；中文文字由 Cocos Label 渲染，不烘焙进图片。
- 原图、差异图和差异坐标必须逐关人工/程序复核，防止出现非预期生成差异。
- 项目最终只引用已复制到 `assets/` 下的正式素材，不引用临时生成路径。

## 4. 技术架构

### 4.1 目录规划

```text
assets/
  art/
    common/                 # 通用背景、按钮、图标、特效贴图
    levels/                 # 关卡缩略图和首包资源
  bundles/
    level-02 ... level-05/  # 本地分包或远程 Asset Bundle
  configs/
    game-config.json
    levels.json
    platform-config.json
  prefabs/
    ui/
    gameplay/
  scenes/
    Boot.scene
    Lobby.scene
    Game.scene
  scripts/
    core/
    gameplay/
    services/
    platform/
    ui/
```

### 4.2 核心模块

- `GameFlow`：启动、首页、选关、对局、结算状态机。
- `LevelRepository`：读取关卡配置、资源地址和差异点数据。
- `DifferenceController`：统一处理两张图的坐标映射、点击命中和同步标记。
- `TimerController`：使用真实时间差计算，避免广告切后台后计时漂移。
- `SaveService`：关卡解锁、星级、最佳时间、设置与广告复活次数。
- `AudioService`：音乐、音效、静音与平台生命周期恢复。
- `AssetService`：主包、分包、CDN 资源加载、缓存、失败重试和版本号。
- `PlatformService`：广告、分享、排行榜、震动、生命周期和系统信息的统一门面。
- `AnalyticsService`：先保留事件接口，后续可接平台统计或第三方统计。

### 4.3 平台适配接口

```ts
interface IPlatformAdapter {
  readonly kind: 'h5' | 'wechat' | 'douyin';
  showRewardedAd(placement: RewardPlacement): Promise<RewardResult>;
  share(payload: SharePayload): Promise<ShareResult>;
  submitScore(score: RankScore): Promise<void>;
  openLeaderboard(): Promise<void>;
  getSafeArea(): SafeAreaInsets;
}
```

- `H5PlatformAdapter`：本地倒计时广告模拟器、Web Share/复制链接降级、本地排行榜。
- `WechatPlatformAdapter`：封装 `wx` 能力，广告位和分享素材由配置注入；排行榜预留开放数据域工程。
- `DouyinPlatformAdapter`：封装 `tt` 能力，预留普通分享、好友邀请/录屏分享和平台排行榜。
- 开发环境可强制指定适配器，浏览器预览不会因缺少 `wx` 或 `tt` 崩溃。

## 5. 激励视频规则

### 5.1 使用场景

- 复活：恢复 1 点生命并增加 30 秒，每局最多 1 次。
- 提示：标记一个尚未找到的差异。
- 加时：增加 30 秒。

### 5.2 完成判定

- H5 模拟器：倒计时走完后才出现“关闭/返回”，任一操作都返回成功。
- 微信/抖音真广告：监听加载、展示、关闭和错误；关闭后按配置决定是否发奖。
- 按当前需求，默认配置 `rewardOnAnyClose: true`，即广告成功展示后，关闭或返回均视为完成。
- 同时保留 `rewardOnAnyClose: false` 的审核安全开关，可切换为只在平台回调“完整观看”时发奖。
- 展示失败、无填充、超时或 API 不可用时不扣次数，给出重试/稍后再试提示。
- 广告期间暂停游戏计时和输入；回到游戏后恢复音频与场景状态。

> 平台通常会返回“是否完整观看”字段。正式提审前需按当期平台广告规范确认是否允许忽略该字段；因此规则必须配置化，不能永久写死。

## 6. 分享、排行榜与外链预留

### 6.1 分享

- 分享内容配置：标题、图片、关卡编号、来源渠道、活动参数。
- 统一参数格式：`level=3&from=share&campaign=default`。
- 微信调用平台分享面板；抖音预留普通分享、好友邀请和录屏分享。
- H5 优先调用 Web Share API，不支持时复制当前链接。

### 6.2 排行榜

- 排名指标：总星数优先，其次通关总用时；同分时先达成者优先。
- H5/开发环境先使用本地假数据，保证 UI 与业务流程可完整调试。
- 微信预留开放数据域、云存储提交和好友榜画布展示。
- 抖音预留平台排行榜提交/展示接口。
- 若需要跨平台总榜，接入自有 HTTPS 服务；客户端只依赖统一 `LeaderboardService`。

### 6.3 外部配置

```json
{
  "cdnBaseUrl": "",
  "apiBaseUrl": "",
  "shareLandingUrl": "",
  "wechatAppId": "",
  "wechatRewardedAdUnitId": "",
  "douyinAppId": "",
  "douyinRewardedAdUnitId": "",
  "rewardOnAnyClose": true
}
```

- 空地址时使用本地资源和本地模拟数据。
- 配置与密钥分离；客户端不保存服务端密钥。
- CDN 资源携带版本清单和哈希，更新失败可回退到已缓存版本。

## 7. 包体与资源策略

- 微信/抖音主包目标控制在 4MB 以内。
- 主包仅包含启动页、公共 UI、字体、音效和第一关必要资源。
- 第 2–5 关配置为 Asset Bundle，可选择平台分包或远程 CDN。
- 场景图优先采用 WebP/平台兼容压缩方案；保留 PNG 源文件但不全部进入发布包。
- 进入选关页后预加载下一关，弱网时显示明确进度和重试按钮。

## 8. 数据配置格式

```json
{
  "id": 1,
  "name": "皇家城堡庭院",
  "timeLimit": 120,
  "maxLives": 3,
  "bundle": "level-01",
  "topImage": "images/base",
  "bottomImage": "images/variant",
  "differences": [
    { "id": "d01", "x": 0.25, "y": 0.42, "radius": 0.045 }
  ]
}
```

- 坐标使用 0–1 归一化数据，彻底避免因屏幕尺寸和图片缩放导致判定偏移。
- 每个差异点可选配置提示描述、判定形状与难度权重。

## 9. 分阶段实施

### 阶段 A：工程重构与可玩骨架

- 保留旧原型作为参考，建立新目录和配置结构。
- 修复等比缩放、坐标换算、双图同步标记和安全区适配。
- 完成启动、首页、选关、对局、失败/胜利流程。
- 用临时素材跑通五关数据，不依赖平台 SDK。

验收：浏览器中可从首页连续游玩 5 关，刷新后保留进度。

### 阶段 B：UI 设计与公共素材

- 先生成一张完整 UI 视觉稿供确认。
- 生成并切分背景、面板、按钮、徽章和功能图标。
- 制作 Prefab、动效、音效占位和多分辨率适配。

验收：720×1280、750×1334、1080×1920 等比例下无拉伸、遮挡或不可点击区域。

### 阶段 C：五关原创场景

- 逐关生成基础图与差异图。
- 录入、校验每关 8 个差异区域。
- 进行可见性、误触率、难度和意外差异检查。
- 生成关卡缩略图与分享图。

验收：每个标注点在上下图均可命中，未标注区域不会误判；无额外生成差异。

### 阶段 D：平台服务

- 接入 H5 模拟广告、分享和本地排行榜。
- 接入微信广告、分享、开放数据域排行榜接口。
- 接入抖音广告、分享与排行榜接口。
- 完成前后台切换、断网、无填充和重复点击保护。

验收：浏览器全流程可测；取得 AppID/广告位后可在两端真机完成最终联调。

### 阶段 E：构建与交付

- 构建 Web Mobile、微信小游戏、抖音小游戏。
- 检查主包/分包大小、首屏速度、内存峰值和低端机表现。
- 输出配置说明、素材清单、关卡制作说明和平台联调清单。

验收：三个目标均能启动，五关可通关，异常退出后数据可恢复。

## 10. 需要后续提供的发布资料

开发骨架和 H5 版本无需等待以下资料；真机商业能力联调时再提供：

- 微信小游戏 AppID、已创建的激励视频广告位 ID。
- 抖音小游戏 AppID、已创建的激励视频广告位 ID。
- 微信开发者工具、抖音开发者工具的已登录测试账号或由项目方执行真机测试。
- 若启用远程资源/跨平台总榜：HTTPS 域名、CDN 或服务端地址及平台白名单配置。
- 最终游戏名、Logo、主体名称、隐私政策和用户协议。
- 分享标题、分享图、客服或官网链接（没有时可先用占位配置）。

## 11. 当前执行顺序

1. 阶段 A：先重构工程并交付五关可玩的无平台依赖版本。
2. 阶段 B：制作一版原创 UI 视觉稿，确认后切分落地。
3. 阶段 C：依次完成五个场景，避免一次生成后整体返工。
4. 阶段 D：完成 H5 适配与平台桥接，待凭据到位后真机联调。
5. 阶段 E：三端构建、性能检查和交付文档。
