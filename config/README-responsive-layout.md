# 设计尺寸与运行时适配（2026-11-02）

## 本次错位原因

上一版自动适配把页面根节点拉宽到浏览器可见宽度，并按控件坐标猜测左右边缘约束。结果是中间玩法图片仍保持竖屏，但体力、提示等控件被推到了窗口两侧。这是运行时布局代码覆盖编辑参数造成的错误。

## 当前规则

- Creator 项目配置的750×1334设计分辨率同时启用 `fitWidth` 和 `fitHeight`，由引擎等比完整显示整张设计画布（SHOW_ALL）。此前配置缺省为仅固定宽度，750×900等矮预览窗口的可见逻辑高度不足，会裁掉1080高签到弹窗的标题和底部；不能只删除弹窗适配而忽略项目策略。
- 设计尺寸直接读取 Creator 的 `view.getDesignResolutionSize()`；项目当前设置为750×1334。代码不再调用 `setDesignResolutionSize` 覆盖编辑器策略，也不改 Canvas 尺寸。
- `Screens` 保留完整设计尺寸，整体居中；可用区域不足时只对整个设计框等比缩小。宽窗口的额外空间不用于拉开页面内部控件。
- 页面内部的位置、宽高、缩放和已有 Widget 参数全部保留。不会给体力、返回、提示、时间等控件推算或添加边缘约束，也不会自动拉伸背景和关卡图片。
- 安全区与平台胶囊通过整体设计框的留白、居中和等比缩小处理，不分别挪动内部节点。
- 弹窗不参与自动适配。签到、设置、结算、解锁等弹窗保留场景或预制体设置的尺寸、位置、缩放和 Widget；不会由本脚本添加居中约束或按安全区缩小。动态加载的弹窗遵循同一规则。
- 点击特效层保持 Canvas 直属以覆盖所有点击，但缩放跟随 `Screens`，避免界面缩小时特效相对变大；点击坐标在生成实例时按当前层换算，不修改特效预制体或动画参数。
- 浏览器尺寸变化、设计分辨率变化和回到前台时重新计算；反复切换不累计缩放。

修改脚本后请重新打开或刷新运行预览。旧版适配在运行时添加过 Widget，仅热替换代码不能保证清除已经生成的组件。Creator 场景与预制体内原有编辑参数无需为此重设。

## 验证

`tools/test-responsive-layout.cjs` 检查短屏、长屏、平板和宽窗口的设计框边界，并检查按钮、图片、背景、已有 Widget、动态体力栏，以及已有/动态弹窗从根节点到内部的尺寸、位置、缩放和约束不被改写；同时覆盖自定义720×1280设计尺寸、重复刷新、窗口切换与监听清理。

`tools/test-touch-point-effect.cjs` 检查特效与界面的缩放比例、点击位置、加载期间切换尺寸、已有特效跟随缩放、重复输入去重和实例回收；TypeScript 检查通过。

本地 Creator 浏览器预览已实际检查750×1334设计模式、1912宽窗口及390×844竖屏下的玩法画面：体力栏、提示、时间、放大按钮均保留在同一竖屏设计框内。浏览器预览验证不代替抖音真机安全区验收。没有通过自动操作保存或丢弃 Creator 中未保存的场景修改。

2026-11-03补充：在默认设计尺寸预览、实际画布高度仅686的窗口中复现签到标题与底部被裁切。通过 Creator 项目设置启用“适配屏幕高度”（宽度原本已启用），确认预览输出的 `screen.designResolution.policy` 从4变为2；重新加载后，签到标题、关闭、七日奖励和领取按钮完整显示。再切换390×844手机预览，弹窗仍完整。此次没有修改弹窗预制体或恢复弹窗自动缩放。
