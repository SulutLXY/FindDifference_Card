# 按章节顺序后台预下载（2026-11-23）

首关仍然只等待当前玩法和当前关卡就绪。进入实际游玩后累计 **3 秒**，先启动主页预热；主页壳预设请求结束后，后台文件队列开始推进。最初的 8 秒只是沿用旧主页预热参数，并非引擎限制，已按要求缩短。

## 顺序

1. MainGameSources 中尚未获取的玩法共用资源。
2. LobbySources 的主页、常用页面和声音资源，排除 SecondaryUI。
3. MainGameAimation 主页动画文件、chapter-covers 章节封面。
4. 按当前 `_cities`（来自主包章节清单）顺序预下载所有章节，包括当前章节剩余内容。每章先配置、缩略图，再按本章关卡顺序获取大图，之后获取惊喜道具预设/动画及章节音乐、连击音效。原始出图标注 JSON 不参与运行预下载。
5. LobbySources/SecondaryUI 的收藏等次级页面，最后 food-icons 中的美食和青花瓷收藏图片。

网络失败的阶段在队尾最多再尝试两轮，已经成功的 UUID 不重复预取。因失败重试而补发的阶段可能出现在收藏资源之后；正常流程严格按以上顺序。

## 玩家选择可以插队

- 玩家打开章节或进入具体关卡，会把该章节尚未完成的后台阶段提到队首。打开主页、章节列表和收藏等页面时，也会优先对应资源包；收藏在这种显式选择下不再等待默认队尾。
- 前台必需资源始终立即按正常加载流程请求，其优先级高于后台的 -10，不会等整个目标章节预下载完才显示页面/进入关卡。
- 后台当前已经发出的单个共享请求允许收尾；完成后停止旧阶段，将玩家刚选中的包提前。不会强制取消引擎中可能被前台复用的请求。
- 多次选择以最近一次为准，重复选择正在预取的包不会重启当前阶段。原阶段保留在剩余队列中，之后重新轮到时跳过成功的 UUID，继续未完成部分。
- 2026-11-24 将选择列表的 Set 展开改为 Array.from，兼容 Creator 的发布 loose spread 转换；队列回归测试也覆盖该转换。
- 在 3 秒延迟结束之前作出的选择也会被记住，队列启动后优先处理；首次自动进入首关不会无故打乱默认共用资源顺序。

## 前台优先与缓存

- 每次只执行一个低优先级资源预取；其依赖下载也限制为并发 1。首关加载和 Feed 预览期间不启动。
- 切关、打开前台页面、暂停、结算、广告、奖励处理、下一关优先预取期间不续发后台请求。已经发出的单个请求允许完成，不强制取消共享的引擎下载。下次有效游玩时从原位置继续。
- 保留现有的“当前关卡就绪后优先预取下一关”机制；全项目队列不会与该任务持续抢占带宽。
- 使用 `preloadAny` 下载文件及依赖，不使用 `loadDir` 实例化全部资源，不创建其他章节的玩法纹理/场景。小游戏沿用引擎磁盘缓存，未设置永久常驻图像引用。
- Web 预览的下载器会生成解码后的 HTMLImageElement，预取后只从 Creator 3.8.8 的 `_files` 原始文件缓存中移除本次同一个图片对象，保留浏览器 HTTP 缓存。不调用图片或 Asset.destroy，避免积累几百张解码图，也不销毁前台纹理。该细节依赖当前固定引擎版本，升级引擎需重新核对。
- 同时最多持有当前后台章节的包清单。MainGameSources、LobbySources、MainGameAimation 是共用包，复用现有加载入口，不交给章节池自动卸载，防止使前台持有的 Bundle 失效。
- 没有持久化一个“永远下载完成”的标志。重新运行时由引擎依据版本化 URL 和实际缓存决定是否下载；资源升级、缓存被清理或空间不足时仍可重新获取。后台失败不阻塞正式进入关卡。

## 时间与可观察性

当前本地构建所有章节目录合计约 210 MiB（运行时队列跳过原始标注文件，另有共用和收藏资源）。一分钟不是保证值：网速、缓存状态、请求延迟、设备帧率都会影响完成时间。玩家随时可以切换到未预取完成的章节，前台按原流程优先加载。

`globalThis.__findDifferenceBackgroundAssets` 保存最新状态，包括当前包、已预取的逻辑资产数、失败阶段数和阶段进度；不是下载字节数或严格百分比。`complete` 表示本次队列全部预取成功，`partial` 表示有限重试后仍有失败。编辑器预览会在阶段切换时输出 `[AssetWarmup]`，发布环境需开启 `__findDifferenceLoadingDebug` 才输出。
