# 按章节顺序后台预下载（2026-11-23）

2026-11-27 更新：首关仍然只等待当前玩法和当前关卡就绪。首关可玩后等待 **3 秒**，先启动主页预热；主页壳预设请求结束后，后台文件队列开始推进。首页、选关、玩法暂停及结算界面均继续计时和下载。首次加载、Feed 预览、前台资源加载、广告和奖励处理仍优先于后台任务。

## 顺序

1. MainGameSources 中尚未获取的玩法共用资源。
2. LobbySources 的主页、常用页面和声音资源，排除 SecondaryUI。
3. chapter-covers 章节封面，紧接首页资源包，优先于第二章节以及其余章节的后台阶段。
4. 按当前 `_cities` 顺序预取每章首屏缩略图（现行选关预设每屏8关），以及前6关的配置、上图和下图；必要的惊喜道具预设/动画、章节音乐和连击音效一并预取。少于6关的章节只取实际关卡。
5. 所有章节入口预取完成后，获取 MainGameAimation 主页动画文件，再按章节顺序补齐剩余配置、缩略图、大图及表现资源。成功的 UUID 跨两轮去重，原始出图标注 JSON 不参与。
6. LobbySources/SecondaryUI 的收藏等次级页面，最后 food-icons 中的美食和青花瓷收藏图片。

2026-11-25 将 chapter-covers 移到 LobbySources 之后、MainGameAimation 之前。以下历史预览记录保留原观测顺序；默认队列以此处的新顺序为准，玩家主动选择仍可插队。

网络失败的阶段在队尾最多再尝试两轮，已经成功的 UUID 不重复预取。因失败重试而补发的阶段可能出现在收藏资源之后；正常流程严格按以上顺序。

## 玩家选择可以插队

- 玩家打开章节时，仅插队预取当前首屏8张缩略图；进入具体关卡时，仅插队预取该关配置、大图及章节必要表现/音频。使用一次性紧急阶段，不提前整个章节余量；完成后恢复默认章节队列的原相对顺序。打开主页、章节列表和收藏等页面时，仍优先对应界面资源包。
- 前台必需资源始终立即按正常加载流程请求，其优先级高于后台的 -10，不会等整个目标章节预下载完才显示页面/进入关卡。
- 后台最多已有两个预取任务在途，选择发生后停止给旧阶段补任务；在途任务全部收尾再将玩家刚选中的包提前。不会强制取消引擎中可能被前台复用的请求。
- 多次选择以最近一次为准，在途请求收尾前不补旧任务。相同紧急阶段不会重启；旧的普通阶段保留在原位，轮到时跳过已成功的 UUID。整阶段已成功的相同阶段也跳过，减少清单重复打开。
- 2026-11-24 将选择列表的 Set 展开改为 Array.from，兼容 Creator 的发布 loose spread 转换；队列回归测试也覆盖该转换。
- 在 3 秒延迟结束之前作出的选择也会被记住，队列启动后优先处理；首次自动进入首关不会无故打乱默认共用资源顺序。

## 前台优先与缓存

- 后台最多同时执行两个低优先级 `preloadAny` 任务，下载器参数 `priority=-10, maxConcurrency=2, maxRequestsPerFrame=2`。一个逻辑任务可能包含依赖文件，并不代表两个整章下载，也不保证网速翻倍。
- 首页、选关、暂停及结算显示期间继续下载；帧更新先推进下载调度，再判断是否推进玩法计时。切关加载、前台页面加载、广告、奖励处理和下一关优先预取期间临时停止续发后台任务，在途任务允许收尾；请求结束后自动恢复。切到应用外时由引擎/宿主决定是否继续执行，不承诺系统后台持续下载。
- 保留现有的“当前关卡就绪后优先预取下一关”机制；全项目队列不会与该任务持续抢占带宽。
- 使用 `preloadAny` 下载文件及依赖，不使用 `loadDir` 实例化全部资源，不创建其他章节的玩法纹理/场景。小游戏沿用引擎磁盘缓存，未设置永久常驻图像引用。
- Web 预览的下载器会生成解码后的 HTMLImageElement，预取后只从 Creator 3.8.8 的 `_files` 原始文件缓存中移除本次同一个图片对象，保留浏览器 HTTP 缓存。不调用图片或 Asset.destroy，避免积累几百张解码图，也不销毁前台纹理。该细节依赖当前固定引擎版本，升级引擎需重新核对。
- 同时最多持有当前后台章节的包清单。MainGameSources、LobbySources、MainGameAimation 是共用包，复用现有加载入口，不交给章节池自动卸载，防止使前台持有的 Bundle 失效。
- 没有持久化一个“永远下载完成”的标志。重新运行时由引擎依据版本化 URL 和实际缓存决定是否下载；资源升级、缓存被清理或空间不足时仍可重新获取。后台失败不阻塞正式进入关卡。

## 时间与可观察性

先覆盖各章前6关，使后续章节入口无需等待前章全部内容。实际耗时仍取决于网速、缓存状态、请求延迟、设备帧率和构建产物；不承诺一分钟完成全项目。玩家可随时切换到未预取完成的章节，前台按原流程优先加载。

`globalThis.__findDifferenceBackgroundAssets` 保存最新状态，包括当前包、已预取逻辑资产数、失败阶段数、阶段进度、在途任务数 `inFlight` 和并发上限 `maxConcurrency=2`；不是下载字节数或严格百分比。`complete` 表示本次队列全部预取成功，`partial` 表示有限重试后仍有失败。编辑器预览会在阶段切换时输出 `[AssetWarmup]`，发布环境需开启 `__findDifferenceLoadingDebug` 才输出。
