# 大关卡独立配置与旧存档兼容（2026-10-21）

## 配置随主包更新

以下两份启动配置位于本地 resources Bundle，使用默认本地构建配置，不在远程 city-configs 中；修改后重新构建并更新平台代码包即可同步：

- `assets/resources/configs/cities.json`：展示顺序及完整章节元信息，由各章源清单生成，启动与存档迁移不读取远程章节包。
- `assets/resources/configs/chapter-rules.json`：旧版资格兼容规则与迁移版本。

GameFlow 分别通过 `resources.load('configs/cities')`、`resources.load('configs/chapter-rules')` 读取，无需从远端取得这两份文件。新增配置不会自动修改已发布的旧代码包，必须重新构建。

每个远程大关卡包包含本章差异点、小关缩略图和玩法大图。`assets/Bundle/levels/<city>/configs/city.json` 是章节源清单，修改后运行 `tools/build-manifest.py` 汇总到主包。大关卡封面放在独立 `chapter-covers` 包，美食图标放在独立 `food-icons` 包。完整布局和释放规则见 [README-content-bundles.md](README-content-bundles.md)。

此次目录迁移首次发布时，需要重新构建并上传所有迁移后的章节包，再更新主包。后续仅新增大关卡时，上传对应新章节包和 `chapter-covers` 的增量，并更新主包总配置。只上传新章节包不会让旧主包发现新章节。为兼容未更新玩家，服务器必须保留旧版共享包及旧版仍引用的哈希文件，不能删除旧资源。增量生成命令见 [内容包说明](README-content-bundles.md#生成上传增量)。

本次调整后的验证范围见 `README-content-bundles.md`；早期阶段记录保留于 `HANDOFF-0.1.3.0-2026-10-21.md`。

## 新规则

选择页标题为「关卡选择」，卡片范围按本章显示，例如「网络热点1-30关」「宠物故事1-20关」「北京1-15关」。长文案在原设计范围内缩排，不增加按钮或卡片尺寸。

每个 `assets/Bundle/levels/<city>/configs/city.json` 独立维护：

- `levels`：本大关卡的小关清单，顺序只在本章内生效。
- 所有专题入口直接开放，不需要观看视频，也不需要先通关其他专题。旧模板的解锁按钮、锁图标和锁定提示均隐藏。
- 所有专题默认免费开放第一关，后续小关通关前一关后免费开放，也可以完整观看激励视频提前永久解锁指定小关。正常通关后点击「下一关」直接进入，不需要观看视频。关卡卡片按进度显示锁和星级，已通关的小关可以重玩。这些公共规则统一由 GameFlow 的 `isCityUnlocked` / `isLevelUnlocked` 实现，不由各章字段配置。

清单生成器不再写入 `unlockMode` 或改写 `prerequisiteCity`。旧源清单遗留字段保留原样但不参与运行时逻辑，汇总到主包时会过滤；新清单不再产生这些字段。这样更新公共规则或新增章节不会仅因规则字段而改变全部旧章节包。

下一关和失败跳过均在本章推进，仅网络热点末关可以衔接2026热梗。2026热梗末关、其他独立大关卡末关不跨入后续大关卡；预加载遵守相同规则。通关完当前独立大关卡可重玩本章。

继续游戏以当前/存档 `lastPlayedCityKey` 为准。成功加载对局后同时保存 `lastPlayedLevelKey`：未通关时继续该关；已通关时向后继续可玩的下一关，不退回跳过的空档。无具体关卡记录的旧存档仍继续本章首个可玩的未通关小关。

## EventTips 解锁确认

- 点击锁定小关先展示场景 `Canvas/EventTips`，不会直接播放广告；已解锁小关仍直接进入。
- `ResultCard/BtnUnlock`：完整观看 1 个视频，永久解锁玩家所选小关并进入；不开放中间跳过的小关。
- `ResultCard/BtnUnlockAll`：每次点击播放 1 个视频，完整观看才累计，显示 `0/3`、`1/3`、`2/3`。不会自动连播；同一弹窗内完成 3 次后，原子写入当前章节清单内全部小关的 `unlockedLevels`，再进入玩家所选小关。
- `BtnClose` 返回按钮和面板外背景空白处关闭弹窗，不触发广告、不穿透点击到下层。切换页面或销毁弹窗也会取消待确认的选关操作。
- **未完成的整章观看进度不持久化**：关闭弹窗或退出游戏后归零，重新打开从 `0/3` 开始。进度不能跨章节继承，关闭前发起的迟到广告回调也不能计入新弹窗。
- 第 3 次视频完成但存档失败时，所有小关资格整体回滚；当前弹窗保留 `3/3`，按钮变为「重试保存解锁」，重试不需要第 4 个视频。关闭后仍清零。
- 视频解锁永久有效，失败重试和重启不重复观看。它与 `completed` 分开保存，不授予星级、积分、美食或通关数。
- 视频解锁第 N 关后，通关即可免费进入第 N+1 关；已通关关卡始终可以重玩，前一关未通关也不重新上锁。
- 视频取消、播放失败均不计数、不解锁。并发点击两种按钮也只发起一个视频；单关视频的迟到成功回调仍保存已赚取的目标关资格，但不自动进入已关闭页面的旧关卡。整章视频关闭后不再累计或授予资格。
- `startLevel` 统一验证资格；下一关加载失败时，仅允许兜底进入本来就已开放的后继关，不能自动绕过视频跳关条件。
- H5 也先打开确认页，确认后的按钮沿用免广告策略（单关点击一次，整章点击三次）；抖音/微信必须完整观看真实激励视频。

旧存档解锁记录及迁移逻辑继续保留以兼容历史数据，但不再参与专题入口判定。提示、加时、复活等奖励广告规则保持原样。

## 两套配置与一次性升级

新配置是上述每章独立 JSON。旧兼容配置为首包的 `assets/resources/configs/chapter-rules.json`，版本为 2，保留历史 8 城市、增加热点后的 10 章节、增加宠物故事后的 11 章节顺序。旧顺序只用于首次迁移，不参与新玩家日常解锁。

- 新玩家创建存档即标记 `chapterRulesVersion: 2`，不执行旧资格恢复，不会自动得到北京等广告章资格。
- 已有 v3 存档缺少该字段时视为旧规则。先按历史顺序计算免费首章及前章全通带来的隐式资格，合并广告解锁记录和已有本章通关记录，写入新存档。
- 兼容不同历史阶段采用旧资格并集，确保以前开放的章节不重新上锁。旧玩家原有北京首章资格也保留，不需要补看广告。
- v2 数字存档先按原城市顺序转换成关卡 key，再强制执行此兼容步骤。
- 未有最后游玩章节记录时，优先继续有部分通关进度、尚未全通的旧章；再选择已开放未全通章节。保留通关星级、最佳时间、评价、积分、库存、成就及其他存档字段。
- 恢复资格、继续章节与新规则版本一次性持久化。写入失败回滚，启动提示失败并允许重试，不消耗或清空旧进度。
- 迁移完成后只使用新配置；不能删除旧兼容配置，否则尚未更新的老用户无法完成首次迁移。

后续需更新并运行 `tools/test-event-tips.cjs`、`tools/test-level-unlock.cjs`、`tools/test-chapter-rules.cjs`、`tools/test-city-unlock.cjs`、`tools/test-city-renumber.cjs`、`tools/test-level-loading.cjs` 等测试，并完成实际构建与老存档验证。重新构建时需发布主包总配置和同次构建的资源增量；旧构建不会自动获得这套规则。
