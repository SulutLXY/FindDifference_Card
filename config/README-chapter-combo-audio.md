## 2026-11-24 发布包专属语音丢失修复

已确认是 11 月 23 日修改引入的发布编译兼容问题，不是两章素材丢失。

旧 `build/douying/assets/main/index.3189a.js` 将展开 Map 迭代器的表达式编译为 `[].concat(r.stages.keys(), variants.keys())`。concat 没有将 Map Iterator 展开为数字档位，随后 Number.isInteger 过滤掉全部元素，导致专属普通答对和连击候选为空。编辑器预览保留原生展开语法；原 Node 测试也只编译到 ES2018，因此未覆盖这条发布路径。

修复：直接检查固定的 `[1, 2, 3, 4, 5]` 五档，避免展开 Map Iterator，继续保持章节专属与通用语音互斥。后台插队去重中新加的 Set 展开也改为 Array.from，避免同一种 loose spread 转换错误。

新增 `tools/cocos-release-transform.cjs`，使用当前 Creator 内置 Babel 的 loose spread 插件运行章节音效、轮换和后台队列测试。新增 `tools/test-built-chapter-audio.cjs`，从实际发布 JS 中提取专属候选、轮换、加载和播放方法，并读取对应构建的章节清单，验证普通答对及五档连击均能到达 AudioSource.play 调用，且所有 13/11 段专属素材都能覆盖。音频加载和播放设备在测试中模拟，此验证不是抖音真机试听。

验证结果：旧发布包准确复现“青花瓷普通答对候选 0，预期 2”。重新生成的隔离包 `build/audio-fix-2026-11-24/douyin`（Creator 构建成功退出码 36）通过实际发布代码验证：青花瓷 13 段、三国 11 段全部进入专属加载/播放路径，无通用语音混入。新主脚本为 `assets/main/index.3dc40.js`。未覆盖原 `build/douying`，原发布包仍需重新构建或改用该隔离验证包。
