# 美食配置维护

编辑 `food-catalog.xlsx` 的“美食配置”工作表，保存并关闭 Excel，然后在项目根目录执行：

```powershell
python tools/build-food-catalog.py
```

仅校验，不修改表格或 JSON：

```powershell
python tools/build-food-catalog.py --check
```

生成文件为 `assets/resources/configs/food-catalog.json`。Cocos 自动导入后，重新预览或构建。
生成器只需 Python 3.9+ 标准库，不需要安装 Excel 或第三方 Python 包。

## 表格字段

- 美食ID：稳定唯一标识，建立后不要随意改动。
- 美食名称、城市ID、城市名称：用于美食收藏列表及详情。
- 关卡目录：如 `level-03`，填写城市内真实存在并列入 city.json 的关卡；空白表示待关联，收藏页仍展示但不自动解锁。
- 素材名称、资产路径：项目相对路径，包含扩展名，如 `assets/Bundle/levels/city-01-beijing/city-01-beijing-BeiJingKaoYa.png`。
- 素材UUID：匹配文件位置的稳定依据。资源移动或改后缀后保留 UUID，工具能找到并回写新路径。刻意换图时需要同步更新 UUID 或清空后按新素材名称定位。
- 美食介绍：最多40字（含标点），在 FoodTips 中展示；空白时显示“美食介绍待补充”。
- 预设评价：填写时为10条，每条2至20字（含标点），用 `|` 分隔，同一道菜不重复。不是其他玩家的联网评价；空白时只展示存在的本机评价。玩家自行输入评价仍沿用50字上限。
- 关联说明：维护说明，不参与运行逻辑。

## 校验与修复

优先按 UUID 唯一匹配，UUID 空白时按现有路径、完整素材名、无扩展名素材名逐级查找。找到唯一文件后修正素材名、路径和 UUID；多个候选、不存在、城市不匹配、重复 ID、重复关卡、缺少 SpriteFrame 或关卡无效时停止生成，保留原 JSON 和表格。

已填写美食名称的美食关卡还会校验名称与配置表是否匹配，防止改动关卡顺序后继续发放旧美食。兼容“南翔小笼 / 南京小笼包”“鸭血粉丝 / 鸭血粉丝汤”“肉丸糊辣汤 / 肉丸胡辣汤”等已有命名差异。

自动修正前备份表格到 `temp/food-catalog-backups`，修复清单在 `temp/food-catalog-validation.json`。生成 JSON 的 `.meta` UUID 在后续运行中保持不变。

收藏页直接读取目录，不再等待所有城市关卡加载；未通关的条目置灰但可以查看详情。通关时依据目录的城市/关卡匹配同一条美食，使用同一份名称、图片、介绍和评价数据。
